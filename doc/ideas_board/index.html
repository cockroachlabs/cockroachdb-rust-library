Ideas-board — the reference app for the CockroachDB Rust library.

Runs offline demos always (changefeed SQL, vCluster tagging, a retry simulator under concurrency). Set CRDB_URL to also run the live-database demo, which fires concurrent upvotes and shows every one landing via execute_tx.

cargo run -p ideas-board CRDB_URL=postgres://root@localhost:26257/defaultdb?sslmode=disable cargo run -p ideas-board

metrics 🔒
Metrics track: attach an in-memory recorder to the pool and read the counters that execute_tx bumps on every transaction and retry.
mrcheck 🔒
Multi-region annotation check (SeaORM path): declare each entity’s intended CockroachDB locality with #[derive(CrdbLocality)], then verify that intent against the live schema at startup. This is the Rust twin of the Spring Boot starter’s startup multi-region check (0.2.0). It is opt-in: call verify after connecting.
multiregion 🔒
Multi-region track: home each idea to a region via the hidden crdb_region column. CockroachDB homes a REGIONAL BY ROW row by the value written to that column on insert — there is no SET crdb_region session statement (a mistake that bit several sibling libraries). This module only ever writes the column value.
semanticsearch 🔒
Semantic-search track: embed each idea’s title into a vector and find the nearest ideas to a free-text query. Uses CockroachDB’s native VECTOR type (v25.2+) for brute-force search; the C-SPANN index (v26.2+) is best-effort.
service 🔒
Ideas-board service: the fundamentals story — a read-modify-write upvote that loses votes under contention, and the one-method fix that absorbs the resulting 40001 serialization conflicts.

run_concurrent_upvotes 🔒
Fires workers × each concurrent upvotes at one idea through the retrying IdeaService::upvote, and returns how many succeeded. Because the upvote runs inside execute_tx, every serialization conflict is retried, so the final vote count equals the number of upvotes fired.
